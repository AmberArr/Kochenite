# Gradle Build

The user selected Gradle after the [Toolchain proof](toolchain-proof.md).
The migration retains the synthetic proof while replacing its build infrastructure.
The production foundation and its key management remain Phase 1 work.

Pinned tools: Gradle 9.5.0 (distribution SHA-256 in wrapper properties), AGP 9.3.1,
Kotlin/Compose compiler 2.4.10, KSP2 2.3.11, JDK 21. AGP supplies built-in Kotlin
for Android modules. Room 2.8.4, SQLCipher 4.17.0 and SQLite 2.6.2 retain the API 36
configuration already verified in the proof. Minimum API is 26. App packaging uses
Build Tools 37.0.0; library tasks use AGP's default 36.0.0.

Use the existing host SDK and default Gradle cache. No emulator is needed.
`proof-domain` is pure JVM Kotlin; `proof-storage` and `proof-ui` are Android
libraries. `app` owns standard debug/release variants and `androidTest` sources.
Tests use constructor/fake boundaries where needed, JUnit and Compose test APIs;
no DI framework or coverage target is introduced.

```sh
./gradlew help
./gradlew build --dry-run
./gradlew :proof-domain:test :app:assembleDebug :app:assembleDebugAndroidTest :app:assembleRelease
adb devices -l
adb -s "$ANDROID_SERIAL" install --user 0 -r app/build/outputs/apk/debug/app-debug.apk
adb -s "$ANDROID_SERIAL" install --user 0 -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s "$ANDROID_SERIAL" install --user 0 -r app/build/outputs/apk/release/app-release.apk
node scripts/run-proof-tests.mjs "$ANDROID_SERIAL"
node scripts/run-release-proof.mjs "$ANDROID_SERIAL"
node scripts/check-proof-apk.mjs app/build/outputs/apk/debug/app-debug.apk "$ANDROID_HOME" debug
node scripts/check-proof-apk.mjs app/build/outputs/apk/release/app-release.apk "$ANDROID_HOME" release
```

Select the connected OnePlus explicitly and confirm its current user. These
commands operate only on the proof packages. The test runner invokes the standard
AndroidJUnitRunner APK generated by AGP and produces sanitized JSON. Gradle's
`:app:connectedDebugAndroidTest` is also available; only use it when device
selection is constrained to the intended serial.

When updating from the old Toolchain standalone test APK, AGP's generated test
APK has version code 0 instead of 1. That one-time update requires `-d` alongside
`-r` on the test-APK installation above. This applies only to
`moe.frost.kochenite.debug.test`, never to the retained release app. No app data
needs to be cleared and no package needs to be uninstalled.

Release proof signing uses the existing ignored `.local/proof-signing` key.
For a fresh checkout, `node scripts/create-proof-key.mjs` creates a temporary
proof key and refuses to replace existing material. The real release identity
and durable signing setup will be established with the foundation. Never put
financial records in this proof: its encryption key is deliberately public.

Future iOS work can introduce Kotlin Multiplatform modules under this Gradle
build. This migration does not implement or claim to test iOS support.

  schema through KSP2. Android Studio IDE sync has not been exercised.

  also passed, establishing a repeat build from clean project outputs.

  4 KB pages. The release add/force-stop/relaunch journey passed after `install -r`.
- Both app APKs passed expected IDs/SDK/debuggability/permissions, signature,
  debug-only code/resource isolation, zipalign and all eight native ELF alignment
  checks. Other Android versions and 16 KB runtime remain unverified.
- `:app:lintDebug` passed with warnings for deliberately retained API/dependency
  versions, unused isolation-marker resource, missing icon, and the proof's older
  backup declaration. Foundation work must supply explicit device-transfer rules
  and app icon. No lint errors were suppressed.
- Gradle initially failed to write its native lock under the existing host cache
  `/home/amber/.local/share/gradle`. Approved execution resolved the sandbox access
  restriction; no environment or cache redirection was applied.
